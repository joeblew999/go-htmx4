# CI: run `mise run check` on every push

**Status:** decided (strict, shell steps only), not started · **Created:** 2026-09-14 09:15

## Goal

Every push and pull request runs `mise run check` on GitHub Actions: `demo:gsxui:test`, `demo:gsxui:workers:smoke` and
`demo:workers:test`, which cover native Go tests plus the real TinyGo builds under workerd. No deploys, no secrets.

## Ground rules

- Same as the demos: tools only from `mise.toml`, **no Node**, upstream docs only, work on `main`, no Docker.
- CI never deploys and never gets Cloudflare credentials.

## Upstream guidance and the Node question

- mise's [Continuous Integration guide](https://mise.jdx.dev/continuous-integration.html) recommends
  `uses: jdx/mise-action@v4`, which installs mise + the repo's tools and caches them. It also documents a **bootstrap
  wrapper** (generated shell script, pinned via `MISE_VERSION`, `MISE_INSTALL_PATH` override).
- `jdx/mise-action` and `actions/checkout` are **JavaScript actions**, executed by the GitHub runner's bundled Node. We
  don't install or call Node ourselves, but it still runs.
- **Decision (2026-09-14): strict no-Node.** Only `run:` shell steps. Check out with `git` (`git init`, fetch `$GITHUB_SHA` using
  `GITHUB_TOKEN`), install mise with the bootstrap wrapper (or mise's standalone install script), then `mise install` and
  `mise run check`. Cache `~/.local/share/mise` with a shell step or skip caching at first.
- Alternative (pragmatic): `actions/checkout` + `jdx/mise-action@v4`, exactly as documented. Shorter, cached, but uses the
  runner's Node for the actions.
