**Status:** Phases 1–3 done (commit `1996440`); open items in **Follow-ups** · **Created:** 2026-09-13 11:09 · **Revised:** 2026-09-13

## Goal

1. **Run gsxui's own demo fully**: the showcase site (ui.gsxhq.dev), every component example,
   and the theme editor, running locally.
2. **Then build our own demo** with the same tooling: gsx + gsxui + htmx 4.

## Ground rules

- **No Node.** No `node`, `npm`, `npx`, Vite or Playwright. Only Go and standalone binaries, pinned in `mise.toml`.
- **Upstream tooling guides only.** Every step cites the gsx / gsxui doc it comes from.
- **No Docker, no deploys.** Everything runs locally. Hosting is the Cloudflare plan
  (`2026-09-13_1111_adopt-workers-go.md`).
- **Don't port the existing starter.** The root app (`main.go`, `templates/`) stays as it is. *(2026-09-14: the root starter was removed; the repo is now just the two demos.)*
- **Work on `main`.** No branches.
- **htmx 4 syntax only** (see Findings log).

## Risks

- **Pre-1.0.** gsx is alpha (`v0.1.0`) and gsxui is untagged. Pin both; `gsxui add --overwrite`
  discards local edits.
- **Harness is test infrastructure,** not a supported product surface. It can change without notice,
  so pin the commit.
- **npm tarballs without npm:** unbundled ESM files may import sub-dependencies. Resolve them from
  `package-lock.json` by hand. If it gets deep, log it and stop.
- **htmx 4 GA vs beta6:** gsxui is only proven on beta6.
- **No live reload** without Vite (upstream-documented trade-off of `--no-web`).

### 2026-09-13: htmx 4 audit of the gsxhq repos

Code review only; nothing built. Reference: https://four.htmx.org/migration-guide-htmx-4/ and
https://four.htmx.org/reference/.

| Repo (HEAD) | htmx dependency | htmx version it targets |
| --- | --- | --- |
| **gsxui** (`c7fd6a8`) | `htmx.org` **4.0.0-beta6**, exact pin, **site only** | **htmx 4.** Site layout uses `hx-boost:inherited`, `hx-swap:inherited="outerMorph transition:true"`. The `ui/` library itself has **no htmx code** (MutationObserver `init()`), so it doesn't depend on any htmx version. Toaster docs suggest `hx-swap-oob="beforeend:#gsxui-toaster"`, which is still valid in htmx 4 (OOB now swaps after the main content). |
| **gsx** (`11dc5e5`) | none | **htmx 2-era tooling.** See below. |
| **gsx-examples** (`a880e97`) | none | No htmx (uses streaming processing instructions). |
| **vite-plugin-gsx** (`ff5f22a`) | none | One comment about staying compatible with hx-boost reloads. |
| **vite**, **gsx-bench**, **gsxhq.github.io** | none | No htmx. |

**gsx's htmx awareness comes from the htmx 2 reference** (`internal/htmldata/htmx-data.json`,
"transcribed from htmx.org/reference/"):
- **LSP completions/docs** offer 9 attributes htmx 4 **removed**: `hx-disinherit`, `hx-inherit`, `hx-vars`,
  `hx-params`, `hx-request`, `hx-history`, `hx-ext`, `hx-prompt`, `hx-disabled-elt`.
  They're **missing** 8 htmx 4 core attributes: `hx-action`, `hx-method`, `hx-config`, `hx-ignore`,
  `hx-status`, `hx-query`, `hx-morph-skip`, `hx-morph-skip-children`. The docs shown for `hx-disable` are the
  htmx 2 meaning, which is now `hx-ignore`.
- **`url_presets = ["htmx"]`** URL-sanitizes only `hx-get/post/put/delete/patch`, by exact name. htmx 4's
  `hx-action` is **not** sanitized. Fix in `gsx.toml`: `[url_attrs] names = ["hx-action"]`.
- The `hx-on*` prefix is treated as JS, so htmx 4 `hx-on:htmx:after:swap` is minified and escaped correctly.
- No open gsx/gsxui issues mention htmx 4.

**Version gap:** htmx 4.0.0 GA shipped 2026-08-28. gsxui is still on beta6 (2026-07-23), and the GA
includes hx-boost, morph and transition fixes.

**htmx 4 rules for gsx markup here:** explicit `:inherited`; `hx-ignore` (not `hx-disable`) to skip
processing; `htmx:after:swap`-style event names; no `hx-ext` / `hx-vars` / `hx-params`. Ignore gsx LSP
suggestions for removed attributes.
