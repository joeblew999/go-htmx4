# Adopt gsxui

**Status:** proposed · **Created:** 2026-09-13 11:09

## Goal

Replace the hand-written `html/template` markup with [gsx](https://github.com/gsxhq/gsx)
components and [gsxui](https://github.com/gsxhq/gsxui) (shadcn/ui ported to gsx), while
keeping htmx 4 as the interaction layer and a single self-contained Go binary as the
deploy artifact.

## What we're adopting

| Piece | What it is | Maturity (as of 2026-09-13) |
| --- | --- | --- |
| **gsx** | JSX-like templating for Go. `.gsx` → `gsx generate` → `.x.go` → `go build`. Stdlib-only runtime, contextual escaping, `gsx dev` live-reload loop. | Alpha, tagged `v0.1.0` (2026-09-03). HEAD `11dc5e5`. |
| **gsxui** | 53 shadcn-style components + Lucide icons. **Copy-in** (`gsxui add` vendors `.gsx` + `.js` into our module as `package ui`); we own the code. Tailwind v4 + CSS tokens (`theme.css`). | Pre-release, **no tags**. HEAD `c7fd6a8` (2026-09-07). MIT + shadcn/Lucide/tw-animate notices. |
| **gsxhq/vite** | Stdlib-only Go ↔ Vite glue: dev-server proxy, manifest-driven prod assets, `/static` handler. | `v0.3.2` |

### Why it fits this repo

- **htmx-native already.** gsxui's own site runs htmx 4 (`hx-boost:inherited` +
  `hx-swap:inherited="outerMorph"`). Its JS core uses event delegation plus a single
  `MutationObserver` `init()` registry, so components re-initialise after htmx swaps /
  morphs with **no htmx-specific code**.
- The toaster is designed for `hx-swap-oob="beforeend:#gsxui-toaster"` — server-driven
  toasts from any htmx response.
- Native-first components (checkbox, radio, switch, native-select, accordion via
  `<details>`) work with zero JS and post normal form values — ideal for `hx-post`.
- Components are type-checked Go; handlers can render a component directly as an htmx
  fragment (`component.Render(r.Context(), w)`), replacing our `{{define}}` fragments.

## Decision: asset pipeline

gsxui needs Tailwind v4 compiled CSS and loads its behaviour as native ES modules.

**Recommended — Option A: official gsx + Vite scaffold.**
`gsxui init` only automates the unmodified `gsx init` npm/Vite layout and refuses
anything else. Node is needed only at dev/build time; the shipped binary embeds `dist/`
and runs no Node. Pin `node` in `mise.toml` so the toolchain stays reproducible.

Fallback — Option B: Node-free. Tailwind standalone CLI (installable via mise) for CSS,
serve `web/gsxui/*.js` as native ESM from `embed.FS`, `gsx dev --no-web`. gsxui's own
Playwright harness does exactly this with an import map, so it's viable — but it's a
manual integration we'd maintain ourselves. Revisit only if Node becomes a hard no.

## Risks

- **Pre-1.0 churn.** gsx is alpha; gsxui has no tags. Pin the gsx module version, pin the
  gsxui CLI to a commit, and upgrade deliberately. `gsxui add --overwrite` discards local
  edits to vendored components — keep edits minimal or isolated.
- **htmx 4 GA vs beta6.** gsxui's site was built against `4.0.0-beta6`; Phase 0 must
  confirm boost/morph behaviour on `4.0.0`.
- **Build complexity.** Adds Node/npm, Vite, Tailwind, and a codegen step to what is
  currently a stdlib-only `go run .`. Accepted trade for the component library; mitigated
  by mise pinning and a single `mise run build`.
- **JS weight.** Import only needed behaviours (deep-import side-effect modules instead
  of the barrel) if bundle size matters.
