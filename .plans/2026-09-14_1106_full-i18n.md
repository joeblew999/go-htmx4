# Full i18n: CLDR-grade formatting, messages, RTL, per-locale live board

**Status:** Phase 0 in progress (scratchpad only) · **Created:** 2026-09-14 11:06

## Decisions made (2026-09-14, your answers)

- **Phase 0: go now**, scratchpad only.
- **v1 locales: the bigger set.** `en` (default), `en-IN`, `de`, `fr`, `es`, `pt` (`pt-BR`, `pt-PT`), `ar`, `he`, `ja`,
  `zh` (`zh-Hans`, `zh-Hant`), `hi` and `ru`. All are in Chrome/Workers' full-data 57, so the workerd oracle covers
  them. Phase 0 still probes `is` as the known gap. More locales are catalog + generator-list work.
- **Browser JS: yes, guarded** (decision 6). This is an AGENTS.md exception for one viewer-local `<time>` behaviour.

## Goal

The app gets **real** i18n, the feature set of ICU / JavaScript `Intl`, done on the server in Go:

- locale negotiation with fallback chains
- ICU-style messages with plurals, ordinals and select
- numbers: decimal, percent, compact, numbering systems
- **currency**: money as integer minor units, CLDR patterns, currency digits
- units and measurement systems
- **dates and times in the viewer's time zone**: styles, skeletons, intervals, 12/24 h
- **relative time that stays live** ("in 3 days", "2 min ago")
- durations and lists ("A, B und C")
- display names (languages, regions, currencies)
- collation (locale-aware sorting)
- text handling: case mapping, NFC, grapheme-safe truncation, bidi
- localized input parsing
- RTL
- SEO alternates

All of it has to work in every place the app renders:

- server-rendered pages
- htmx fragments
- hx-ws pushes
- error responses

It must keep running under TinyGo on Workers and under `go run .`, with identical output. Adding a locale should
mean adding one catalog and listing the locale for CLDR generation, with no view or handler changes. Tests must fail on
a hard-coded string, a missing translation, an unprefixed URL, or output that disagrees with ICU.

## Decisions needed (recommendations first)

1. **Locales for v1.** Recommend:
   - `en` (default, with `en-IN` for Indian digit grouping)
   - `de` (text expansion, `1.234,56 €`)
   - `ar` (RTL, six plural forms, Arabic-Indic digits)
   - `ja` (CJK, no plurals, era calendar available)

   Pseudo-locales `en-XA` (accented, ~40% longer) and `ar-XB` (RTL) are test-only.
2. **URL scheme.** Recommend a path prefix per locale (`/de/board`). The default locale stays unprefixed and is
   `x-default`. No redirects based on Accept-Language (Google's guidance; Googlebot sends none). An explicit choice
   sets a cookie, and only a bare `/` honours it. Unknown prefixes give 404.
3. **Server formatting engine.** Recommend **C + oracle**. Engine D (Cloudflare's own `Intl`) was the obvious
   shortcut, but Cloudflare's `Intl` isn't full:
   - **What Cloudflare has.** Workers support "all of the standard built-in objects supported by the current Google
     Chrome stable release" ([web standards](https://developers.cloudflare.com/workers/runtime-apis/web-standards/)),
     so `Intl` is there.
   - **What's missing** (reported by [cldr-is](https://github.com/gudrodur/cldr-is), confirm in Phase 0):
     - Workers embed **Chromium's filtered ICU data**, the same as desktop Chrome, measured identical on local workerd
       and the live edge.
     - Chromium keeps full data only for languages its own UI is translated into.
     - For other locales (Icelandic, for example), `DateTimeFormat`, `NumberFormat`, `RelativeTimeFormat`,
       `ListFormat` and `Collator` silently fall back to `en-US`; only `PluralRules` is right.
   - **Time zones** ([workerd#7256](https://github.com/cloudflare/workerd/issues/7256), open): workerd's embedded
     tzdata predates IANA 2026c, so Casablanca resolves to the wrong offset from 2026-09-20.
   - **So D can't be "full".** It covers our v1 locales (de, ar, ja are Chrome UI languages) but not every locale we
     might add. A D+C hybrid would be two engines rendering the same pages.
   - **D. Runtime `Intl` via `syscall/js`** is therefore rejected as the engine. It stays useful as the **oracle** for
     Chrome-covered locales, and CLDR test data covers the rest.
   - The **C + oracle** option, in detail:
   - **C. Our own CLDR generator.** `cmd/cldrgen` reads [cldr-json](https://github.com/unicode-org/cldr-json)
     48.2.1 at generate time. It writes per-locale Go tables for the supported locales only, plus a pure-Go runtime
     (future `kit/i18n`). This gives TinyGo-safe code, native = Workers output, and a controlled size.
   - **Oracle: workerd's V8 `Intl`** (full ICU, assuming Phase 0 confirms it). A local-only shim in `workerd/`
     generates golden outputs, and `go test` compares the Go engine against them. It's the same engine family as
     production, with no Chrome and no Node.
   - **Rejected as the engine:**
     - `golang.org/x/text` v0.42.0: no dates, relative time, lists, units or intervals. Its numbers and currency are
       partial, though `collate` and `display` stay candidates for those two features.
     - `go-playground/locales` v0.14.1: CLDR 36.0.1 (2019), `float64` currency, no relative time, lists, units or
       display names.
     - `go-i18n` v2.6.1: messages only, and it links `text/template`.
   - **Alternative D: call workerd's `Intl` at runtime via `syscall/js`.** It adds zero wasm size and gives full ICU,
     but `go run .` and `go test` have no `Intl`, so native and Workers output would differ. Rejected unless C blows
     the size budget.
4. **Message syntax.** Recommend **ICU MessageFormat 1** in `locales/{locale}.toml`: `plural`, `selectordinal`,
   `select`, and `number`/`date`/`time` arguments with skeletons. Translators and tools know it. It's parsed at
   generate time into typed Go methods, so there's no runtime parser and a missing key is a compile error. MF2 is the
   newer Unicode standard but has little tool support yet.
5. **Viewer preferences.**
   - Precedence: explicit setting (cookie) > Cloudflare's `request.cf` (`Timezone`, `Country` via workers-go
     `fetch.NewIncomingProperties`) > locale defaults > UTC.
   - Preferences: locale, time zone, display currency, hour cycle, first day of week, measurement system.
   - A settings dialog built from gsxui components.
   - `go run .` has no `cf`, so it falls back to locale defaults + UTC.
6. **Viewer-local enhancement in the browser.** Fragments are cached in the Room and pushed later, so server-rendered
   "2 min ago" goes stale, and the server only guesses the viewer's time zone (from `cf`). Recommend:
   - Go renders the finished text inside `<time datetime>` (crawlable).
   - A small behaviour re-formats every `<time>` with `Intl.RelativeTimeFormat` / `Intl.DateTimeFormat`, using the
     page's `lang` and the browser's real time zone. It runs on load, after each htmx swap and hx-ws push, and on a
     timer. This is the same pattern as GitHub's `relative-time` element.
   - **This needs a JS exception to AGENTS.md** (JS today is only the Worker entry, the DO and local shims).
   - The alternatives:
     - A server-authored schedule (`[instant, text]` pairs, JS only swaps text): byte-identical with engine C, but no
       real viewer time zone.
     - htmx `hx-trigger="every 60s"` re-rendering: no JS, but ~17 Worker requests/s per 1,000 tabs.
7. **Calendars.** Recommend Gregorian in v1, with the `-u-ca-` extension (Japanese era, Islamic, Buddhist) in a later
   phase once the generator exists. Numbering systems (`-u-nu-`) are in v1.
8. **Currency and unit conversion.** Recommend: formatting only.
   - Amounts carry their own ISO 4217 code, and we never convert money: exchange rates are data, not i18n.
   - Units convert only where a preference asks (km ↔ mi, °C ↔ °F) and for display only.
9. **Translations source.** Recommend hand-maintained catalogs with `en` as the source. Machine drafts (Gemini or
   Workers AI via fnox) would be ⚠ outward-facing on every run.
10. **gsxui hard-coded English.** Recommend passing labels as attributes where components forward them, and ⚠ upstream
    gsxui issues for label props elsewhere. Aria-labels such as "Close", "Loading" and "Go to next page" are affected,
    and gsxui's `docs/jsx-parity.md` lists calendar i18n as a gap. Don't edit the vendored `ui/`. Calendar waits for
    an upstream locale parameter, or we contribute one using our engine.
11. **Size budget.** Workers limits compressed script size by plan (verify our plan on the limits page). Today
    `app.wasm` is 2.05 MB raw / 660 KB gzip. Recommend a budget of +800 KB gzip for 4 locales, including tzdata,
    enforced by a `mise run check` assertion.
12. **Sequencing.** Recommend Phase 0 now (scratchpad only). The rest follows
    [one-app](2026-09-14_1037_one-app-template-and-kit.md) Phase 2, so we translate the merged pages once. The engine
    lands as `kit/i18n` with one-app Phase 3, and one-app Phase 7's ⚠ deploy ships it.

## Ground rules

- Same as the app: no Node, TinyGo for everything on Workers, plain-path routes + `allow()`, and gsx for all markup.
  Credentials come from fnox. GUI is gsxui only. Deploys, external APIs and upstream issues need your OK.
- Every tooling step cites its upstream guide. Demo-first: upstream examples run in the scratchpad first, then **our
  own demo**, a `/formats` showcase page that grows with each phase before the app pages use it.
- **The server HTML is always complete and localized.** Crawlers that don't run JS see finished text, and so do AI
  fetchers, link previews and no-JS visitors. The browser's `Intl` only *enhances* what depends on the viewer: their
  time zone, live relative time, client-side sort and filter. It always gets the page's locale
  (`document.documentElement.lang`), never the browser default. See "Browser `Intl` and Google" below.
- CLDR data is read at generate time only. The generated tables are committed, like vendored data, and never
  hand-edited.

## Upstream guidance

- **CLDR**
  - [cldr-json](https://github.com/unicode-org/cldr-json) 48.2.1 (latest tag, checked 2026-09-14).
  - [LDML spec](https://unicode.org/reports/tr35/) parts: Numbers (patterns, currencies, compact), Dates (patterns,
    skeletons, intervals, time zone names, relative fields), General (units, lists, display names), Plural rules,
    Collation.
- **ICU MessageFormat:** [ICU user guide: formatting messages](https://unicode-org.github.io/icu/userguide/format_parse/messages/).
- **IANA time zones in Go:** [`time/tzdata`](https://pkg.go.dev/time/tzdata) embeds the database. Check TinyGo's
  support and size in Phase 0.
- **gsx**
  - [Context](https://github.com/gsxhq/gsx/blob/v0.1.0/docs/guide/syntax/context.md): ambient `ctx` in every
    component, with locale as a listed use.
  - [Pipeline filters](https://github.com/gsxhq/gsx/blob/v0.1.0/docs/guide/config.md): `func(ctx, value, args…)`
    registered in `gsx.toml`, e.g. `{ n.CreatedAt |> relTime }`.
- **gsxui RTL** (`.upstream/gsxui/site/pages/rtl.gsx`, pin c7fd6a8)
  - `dir="rtl"` on `<html>` is enough: logical classes, `rtl:rotate-180`, direction-aware floating UI, mirrored keys.
  - Sheet, Drawer and Sidebar `side` stays physical.
  - Fonts: Noto Sans Arabic as a fallback after Geist.
- **workers-go** `cloudflare/fetch/property.go`: `IncomingProperties.Timezone`, `.Country`
  (`_examples/incoming`).
- **Google**
  - [Multi-regional and multilingual sites](https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites):
    separate URLs per language, no redirects based on perceived language, content language read from visible text.
  - [hreflang](https://developers.google.com/search/docs/specialty/international/localized-versions): reciprocal
    alternates plus `x-default`.
- **Cloudflare**
  - [Workers limits](https://developers.cloudflare.com/workers/platform/limits/): script size, CPU time.
  - [DO WebSocket Hibernation](https://developers.cloudflare.com/durable-objects/best-practices/websockets/):
    `acceptWebSocket(ws, tags)`, `getWebSockets(tag)`.

## Browser `Intl` and Google

The browser's `Intl` works **with** Google, as long as it only enhances server HTML and never replaces it:

- **Google renders JS** with evergreen Chromium ([JavaScript SEO basics](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics)).
  Client-formatted text can be indexed, but rendering can lag the crawl. Google still recommends server-side rendering
  because "not all bots can run JavaScript".
- **Not everything we want to reach runs JS.**
  - The search plan wants Gemini grounding and the user-triggered `Google-Agent` / `Google-GeminiNotebook` fetchers,
    which need pages that "work as plain HTML".
  - Other search engines, AI crawlers and link previews mostly don't render JS either.
  - So finished text has to be in the server HTML, and a client-only formatting design fails them.
- **The renderer's locale and time zone are Google's, not the visitor's.** Googlebot crawls from US IPs with no
  Accept-Language, and the renderer's `navigator.language` and time zone aren't documented. If client code used the
  browser default, a `/de/` page could be indexed with US-English dates: mixed-language content on a German URL. So
  client `Intl` always takes the page's `lang`. The time zone difference is harmless for indexing (a time shifts, the
  language doesn't).
- **Browsers have the same locale gaps as Workers.** Desktop Chrome/Edge drop full data for languages their UI isn't
  translated into, and Google's renderer is Chromium. For such a locale, client `Intl` would replace our correct server
  text with `en-US` text, both for visitors and in Google's rendered page. So the behaviour **feature-detects** before
  re-formatting (`Intl.DateTimeFormat.supportedLocalesOf([lang])` plus a probe that the resolved locale isn't `en`) and
  otherwise leaves the server text alone.
- **Avoid visible reflow.** If the client reformats server text into something different, the page flickers and shifts
  layout. The re-format targets only `<time>` and explicitly marked values, and only changes what depends on the
  viewer (time zone, elapsed time).
- **Verify, don't assume.** Phase 8 checks `/de/` and `/ar/` in Search Console's URL Inspection → "View crawled page"
  (rendered HTML + screenshot): language, digits and dates as expected.

## Design

- **Request context.**
  - A middleware strips `/{locale}` (plain-path ServeMux) and resolves preferences (decision 5).
  - It stores an `i18n.Context` (locale, time zone, currency, hour cycle, units, week) in `r.Context()`.
  - `writeNode` renders with it, so components call `i18n.From(ctx)` or pipeline filters. No locale parameters.
- **Engine layout.**
  - `kit/i18n`: runtime, stdlib only.
  - `kit/i18n/cldr`: generated per-locale tables.
  - `cmd/cldrgen`: fetches the pinned cldr-json tag, keeps only the listed locales and their parents, and writes Go.
  - `cmd/msggen`: `locales/*.toml` → typed Go.
  - `mise run i18n` runs both.
- **Money.** `i18n.Money{Minor int64, Currency string}`, never a float. Rounding and digits come from `currencyData`.
- **Time.**
  - Instants are stored as UTC RFC 3339.
  - Rendering uses the viewer's zone. That needs tzdata, so the zone database is embedded; Phase 0 measures the size
    under TinyGo.
  - Every rendered date is `<time datetime>`, and every rendered number that matters is `<data value>`.
- **URLs.** One helper builds every in-app URL: `href`, `hx-get`/`hx-post`, `hx-ws:connect`, form `action`.
  `/static/`, `/assets/` and `/gsxui/` stay unprefixed. Fragments inherit the locale through their prefixed URL.
- **Direction.**
  - `<html lang dir>` comes from the locale.
  - The locale switcher is links that opt out of boost (`hx-boost:inherited="false"`), because boosted navigation
    swaps only `<body>`.
  - Each switcher item is labelled in its own language with `lang` and `hreflang`.
- **Live board.** One Room per topic, so presence stays one count.
  - `/live/{topic}?locale=de` is validated in `index.mjs` against Go's list, with a shared-rule test.
  - The Room calls `acceptWebSocket(server, [locale])`.
  - Go publishes one fragment per locale in one request, and the Room keeps `last` per locale and sends each tag its
    own HTML.
  - Presence becomes count-only, with a translated label rendered by Go.
  - **Time zones are not per socket.** Pushed fragments show relative times (a schedule with absolute instants works in
    any zone). The absolute tooltip uses a zone-free format with a UTC label, or the schedule's final text.
- **Oracle and goldens.**
  - `workerd/intl-oracle.mjs` (local-only shim) plus `mise run i18n:golden` run a case table through `Intl` in workerd.
  - They write `kit/i18n/testdata/golden/*.json`, and `go test` compares the Go engine against them.
  - CLDR versions must match: pin cldr-json to the CLDR major of workerd's ICU (Phase 0 finds it). Known ICU-vs-CLDR
    differences go in an explicit allowlist with reasons.
- **Tests (`mise run check`)**
  - engine goldens
  - catalog completeness, with the same placeholders and each locale's CLDR plural forms
  - **hard-coded text:** every page and fragment rendered in `en-XA`; any untranslated text node or `placeholder` /
    `aria-label` / `title` fails
  - URL prefix audit
  - logical-class audit
  - `TestBoardFragmentWireFormat` for every locale
  - size budget
  - Workers smoke: `/de/`, `/ar/formats`, an unknown prefix (404), and a formatted date and currency byte-identical
    between native and TinyGo
  - e2e (one-app Phase 6): `ar` screenshots, `en-XA` overflow, switcher round-trip, mixed-locale two-tab push, a live
    relative-time tick

## Findings

### 2026-09-14: Chrome / Workers `Intl` gaps (from Chromium's ICU filter; behaviour still to confirm in Phase 0)

Source: [`chromium/deps/icu` `filters/common.json`](https://chromium.googlesource.com/chromium/deps/icu/+/refs/heads/main/filters/common.json),
the desktop filter behind V8's ICU data. [cldr-is](https://github.com/gudrodur/cldr-is) reports workerd and the live
edge match desktop Chrome exactly.

**By language.**
- **153 languages** get the basic locale tree (Chrome's Accept-Languages list).
- **Only 57 of them** also get currency, region, unit and time zone data:
  `af am ar bg bn ca cs da de el en es et fa fi fil fr gu he hi hr hu id it ja kn ko lt lv ml mr ms nb nl pl pt ro ru sk
  sl sr sv sw ta te th tr uk ur vi zh` (plus legacy aliases `in iw mo no sh tl`). Collation has roughly the same list.
- **95 languages are partial.** For these, cldr-is measured `DateTimeFormat`, `NumberFormat`, `RelativeTimeFormat`,
  `ListFormat` and `Collator` falling back to `en-US` (only `PluralRules` right):
  `ak an as ast ay az be bho bm br bs ceb chr ckb co cy doi dv ee eo eu fo fy ga gd gl gn ha haw hmn ht hy ia ig ilo is
  jv ka kk km kok kri ku ky la lb lg ln lo lus mai mg mi mk mn mni mt my ne nn nso ny oc om or pa ps qu rm rw sa sd si
  sm sn so sq st su tg ti tk tn to ts tt tw ug uz wa wo xh yi yo zu`.
- **Every other CLDR locale has no data at all.**

**Trimmed even for the 57 full languages.**
- Relative weekday fields ("last Monday", "next Tue") are removed.
- Localized time zone names for ~420 zones are removed, so output falls back to GMT offsets.
- Unit names: grammatical case and gender are dropped, and names are allowlisted.
- Currency narrow symbols and plural names are allowlisted.
- Macro-region names (World, Europe, Latin America…) are removed.
- Language display names exist only for the Accept-Languages set.
- `measurementSystemNames`, `personNames` and exemplar characters are removed.
- Chinese `unihan`/`big5han`/`gb2312han` collations and UCA rules are removed.
- Transliteration is limited to Latin-ASCII and kana.
- Plus workerd's stale tzdata ([workerd#7256](https://github.com/cloudflare/workerd/issues/7256)).

**Consequences for this plan.**
- The v1 locales (`en`, `en-IN`, `de`, `ar`, `ja`) are in the full 57, but still hit the trims above.
- Engine C, generated from full CLDR, has none of these gaps.
- The workerd oracle is valid only for the 57 languages and only for untrimmed fields. The client `Intl` guard (see
  "Browser `Intl` and Google") must treat the 95 partial languages as unsupported.
- Other browsers trim ICU differently; Phase 0's drift check covers Safari and Firefox.
